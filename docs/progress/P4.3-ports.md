- The native `forwardLocal` listener binds any free phone port; the Swift tunnel re-bound the last port so a reload kept its origin. After a pause/reopen the page is reloaded at the new port with the same path (`tunnelUrl`), but origin-scoped storage resets. If that matters, add an optional preferred local port to `forwardLocal` in modules/ssh (new task `P4.3d-forward-preferred-port`).
- The native listener gives no per-channel failure record, so "nothing answered / forwarding refused" is learned by opening one probe channel (`SessionTunnel.lastFailure`) when the page fails, which the Swift tunnel got from its own pump. A server that logs every accept will see one extra, immediately closed connection on failure.
- The 6 s remote watchdog around the discovery script (`runBoundedScript` markers) is not ported; the 8 s local exec timeout bounds the call. A Host whose shell ignores the timeout simply gets `timedOut`.
- `FakeTransport` has no ports surface (Swift `transportsWithoutPortDiscoveryDeclineThePreview`); the demo Host is a `FakeSession` subclass that prints the canned discovery output. A real `FakeTransport` hook can come with the transport wiring.

- Failure text stays unresolved in core (`Text`, or `{ transport }` for a transport presentation) and the app renders it through the catalog (`portsText`/`portsMessage`).
- `react-native-webview`'s default export is a generic class whose `P = undefined` collapses its props to `never` under TS 6, so the view is instantiated as `<WebView<object>>`.
- Web view hardening mirrors Swift D7: `incognito` (non-persistent store), no message handler or bridge, `setSupportMultipleWindows={false}`, top-level navigation decided by `decideNavigation`, downloads refused with a notice.
- Strict-mode caveat: the list route closes the store when it unmounts; Expo Router does not enable React StrictMode in this app (no `reactStrictMode` experiment), so the dev double-effect would not close a live store.
- Differences from Swift: no `ProgressView` bar from KVO, progress comes from `onLoadProgress`; the preview history is not kept across a pause (the view remounts, `key = loadId`), only the page path.
