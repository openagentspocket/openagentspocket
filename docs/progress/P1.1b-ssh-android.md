notes:
- Base: the judge's dependency note; this branch is cut from P1.1a's branch so both sides implement the same `src/bridge.ts`. Not a line of the TS layer changed besides comments; `client.ts` (Host Key policy), `streams.ts`, `sftp.ts` run as-is on Android.
- Two-step connect over JSch's one call: `HostKeyGate` is the session's `HostKeyRepository`; JSch asks it after verifying the server's signature and before user auth, and it holds that thread until `authenticate` (accept) or `disconnect`/10 min (reject). The user name is set at `authenticate` through `com.jcraft.jsch.AgenticoSessionAccess` (JSch's `Session.setUserName` is package-private). Host certificates are left out of `server_host_key` (the app pins plain keys).
- Device keys: a 32-byte Ed25519 seed (BouncyCastle) sealed with AES-256-GCM by a non-exportable Android Keystore key (alias bound as AAD), stored in `noBackupFilesDir/agentico-ssh-keys/<sha256(alias)>.key`. A blob that no longer opens is `keyCorrupt`, never silently regenerated (as iOS). The JSch `Identity` only signs.
- SFTP: JSch's `ChannelSftp` globs paths (`*`, `?`), always renames with posix-rename when offered, and cannot open with O_EXCL, so `SftpClient` speaks SFTP v3 itself over a `subsystem` channel: OPEN with CREAT|EXCL + mode, plain RENAME for no-overwrite, `posix-rename@openssh.com` for overwrite, up to 16 READ/WRITE requests in flight. A timeout or malformed reply marks the client unusable (`sftpUnavailable` after), since the reply stream is out of step.
- Streams: JSch writes incoming bytes from its session thread and opens the window as soon as the write returns. `StreamPipe` buffers until `startStream` and blocks that thread only past 4 MiB unread, which stalls every channel of the connection, not just the unread one (iOS holds back only that channel). A pump thread per started stream emits `onStreamData` in order and then `onStreamClose` once (PTY: waits up to 2 s for the channel close to read the exit status). Writes go through one thread per stream; a write timeout leaves the write queued.
- JSch on Android: its base `JavaVersion` answers 8 (D8 ignores the multi-release classes), so it uses its BouncyCastle Ed25519, X25519 and ML-KEM; negotiated here: `mlkem768x25519-sha256`, `ssh-ed25519`, `aes128-gcm@openssh.com`.
- Running the harness: Metro on its own port (`-PreactNativeDevServerPort=8091` at build time, `expo start --port 8091`), `adb reverse tcp:47451 tcp:47451` for the fixture, deep link via `adb shell am start -a android.intent.action.VIEW -d '<agentico:///__ssh?...host=10.0.2.2...>'`. Start Metro without `CI=1` if you edit JS while it runs: `CI=1` turns off the file watcher. The backend ran with `--root /tmp/agp11b` (short for AF_UNIX) and was stopped afterwards; the emulator was shut down and the native slot released.
