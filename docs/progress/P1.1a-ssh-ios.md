notes:
- Wiring: one CocoaPods pod `AgenticoSSH` (Swift 5 language mode, iOS 18). The Swift package's C target became a module map under `CAgenticoSSHSupport/include` found through `SWIFT_INCLUDE_PATHS`; the app target needs that path too (the AgenticoSSH swiftmodule records the C module), so the podspec sets an absolute `user_target_xcconfig` path (fine: `ios/` is generated). Expo SDK 58 SwiftPM support exists only for prebuilt packages, so CocoaPods `vendored_frameworks` was the path.
- `Double.init`/`Int.init` passed as function references are ambiguous in Swift 6.x with ExpoModulesCore in scope; use closures.
- Host Key policy lives in TS (`checkHostKey`) between native `connect` (handshake only) and `authenticate`, so no auth starts before the key is accepted; `FakeSsh` uses the same function.
- Streams: native reading starts at the first `onData` listener (`startStream`), so early bytes are never lost and an unread channel holds the server back; every stream reports `onStreamClose` once. Bytes cross as base64 both ways (`bytes.ts`, no reliance on Buffer/atob/TextDecoder).
- SFTP `write` is exclusive-create (the package opens O_EXCL); `{ replace: true }` stages a hidden sibling and renames over atomically.
- The isolated sshd's SFTP starts in the account's real home (ForceCommand only fixes `$HOME` for shells): the harness works only under `$HOME` from exec (the isolated root). Keep it that way.
- The COpenSSL XCFramework carries the upstream Heeler author's code signature (kept: the artifacts stay byte-identical so `SHA256SUMS` verifies). ~20 MB of binaries are committed, as in the Swift repo.
- Deep links from `simctl openurl` show an "Open in Agentico?" prompt; a one-line Maestro `tapOn: "Open"` clears it.
