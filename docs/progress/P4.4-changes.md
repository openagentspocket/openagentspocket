notes:
- Paths and patch bytes are "byte strings" (JS strings of 0-255 units, `bytes.ts`) so they stay Map keys, sort in byte order and round-trip; display goes through `displayText` (control pictures, lossy UTF-8).
- Display strings are never built in core against an i18n runtime: functions take a `Say` (`say.ts`); `CHANGES_KEYS` lists every catalog key used and `changes.test.tsx` pins that each exists in en and es. The app's `say` is `translate(getLocale(), 'app', ...)`.
- Stores are framework-free `Observable`s (`getState`/`subscribe`, `useSyncExternalStore` in `useStoreState`); clock, `now`, Host gate, agent status source and readers are injected, so tests run on `FakeClock`.
- Differences from Swift worth knowing: the trailing text after a patch's last newline is not a line (Swift would count it as a blank context line when hunk counts remain); the agent status source may call its listener synchronously, which replaces `applyBufferedOpeningStatus`; commit age is returned as `{unit, count}` and formatted by the app with `Intl.RelativeTimeFormat`; word diff uses an LCS over code points, not grapheme clusters.
- Reused: `Clock`/`FakeClock`/`CancelSignal`/`createCancellation`, `TransportFailure` + `explanation`/`userFacingDescription`, `encodeUtf8`/`decodeUtf8`, `AgentStatus`, `DiffView`/`parseUnifiedDiff` types from packages/ui (the diff screen adapts the structured patch to `DiffLine`), ListRow, Banner, ErrorState, EmptyState, Chip, VirtualSectionList, copyToClipboard.
