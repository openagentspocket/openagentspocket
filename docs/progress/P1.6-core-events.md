notes:
  - Layout: `EventsSessionCore` (state, run loop, transport install, keepalive, teardown) + `EventsSession` (public API) because a TS class cannot span files and the port is ~650 lines. Pure TS: no platform timers, no TextEncoder, no AbortController types; the clock and the frame scheduler are injected.
  - Failures are `{ kind }` values named after the Swift `TransportError` cases, thrown as `TransportFailureError`. Swift's `CancellationError` and `TransportError.cancelled` are one `cancelled` kind here. Public calls accept an AbortSignal-compatible `CancelSignal`.
  - The session applies the floor on every ping it makes (connect, keepalive, revalidate); `EventsTransport.ping()` returns the raw `{ version, protocolVersion }`.
  - Deliberate deviation: Swift drops a distrusted Transport and relies on ARC `deinit` to close the SSH connection. JS has no deinit, so distrusted Transports are retired and closed explicitly at the next redial or teardown. Redial path: "closes a distrusted transport before its redial dials" (closed while the second dial is still parked) and "redials at once after a terminal hits a dead link". Teardown path: "closes a distrusted transport on teardown even before any redial" (a retryable drop parks the run loop in backoff with the Transport still installed, a failing terminal distrusts it, then `suspend()` must close it with no second dial). The earlier version of that test only reached the redial's close.
  - Bounded channel I/O (review fix): `openEventsChannel` arms the 15 s request deadline before the subscribe write and does not await the write on its own (a rejection goes to `shutDown`), so a write that never settles rejects with `timedOut` and closes the duplex. Swift gives the write its own `requestTimeout` and then the ack another deadline; here one 15 s budget covers both (stricter, never longer). `end()` races the duplex close against `CHANNEL_CLOSE_TIMEOUT_MS` (2 s, Swift `close(timeout: .seconds(2))`) on the injected clock and finishes the events either way, so a wedged native close cannot hold `suspend()`/`end()` or the serialized lifecycle behind them.
  - `ScriptedEventsTransport.failNextSubscription(failure)` scripts a failing subscribe (timed out, rejected) on a connection that still reports `isConnected()`.
  - Not ported: the two Swift tests that need HostConsoleProjection / AttachTerminalStore (P2.1, P3.1); their session-level property ("a terminal starts before the events subscription is ready") is covered. The Windows remote-api-bridge is just another `EventsDuplex`.
  - `FakeClock`, `ScriptedEventsTransport`, `CallGate`, `SequencedConnector` are exported from core (like the existing `FakeTransport`) so P2.1 can script sessions. FakeClock takes a `settle` function: in Node tests `() => new Promise((r) => setImmediate(r))`.
  - No dependency added.
