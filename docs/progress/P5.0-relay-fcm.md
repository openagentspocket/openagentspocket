notes:
  - Relay layout: worker.js is routing only (404 -> 163 lines, out of the ratchet baseline); apns.js holds the moved APNs
    code unchanged in behavior; fcm.js + fcm-auth.js are new; jws.js (base64url, PEM, compact JWS) and common.js (json,
    alert-body validation shared by both platforms) are shared.
  - Config is per platform: a relay serves what it has credentials for. Neither configured -> 500 before reading the body
    (as before); a request for an unconfigured platform -> 500 relay_misconfigured.
  - New relay secrets/vars: `FCM_SERVICE_ACCOUNT_JSON` (secret, the downloaded key file) and optional `FCM_PROJECT_ID`
    (defaults to the account's project_id). Token endpoint and scope are fixed constants, not read from the JSON.
  - New errors: `bad_platform` (400), `fcm_unreachable` (502). Success on FCM answers `{"fcmId": "<message id>"}`.
  - FCM keeps at most 4 collapse keys per offline device; per-pane collapse keys can exceed that (documented in the
    relay README). The Android app should tag its local notification per pane to replace older ones on screen.
  - `priority` is lowercase `"high"` as the FCM v1 reference documents.
  - Dependencies: none added.
